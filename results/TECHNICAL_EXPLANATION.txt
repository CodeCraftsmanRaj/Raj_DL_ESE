EXP 1: MULTILAYER PERCEPTRON (MLP) - mlp.py
================================================================================

OVERALL OBJECTIVE:
Design a neural network for digit classification and analyze the effect of 
changing activation functions, layer depth, convergence, and stability.

SUB-EXPERIMENT 1: Activation Function Impact
REQUIREMENT:
- Design a neural network for digit classification and analyze the effect of 
  changing activation functions.

IMPLEMENTATION:
- Class: MLPActivation (nn/Module)
- Tests: ReLU, Tanh, Sigmoid
- Architecture: 784 -> 128 -> 64 -> 32 -> 10 (4 dense layers)
- Training: 10 epochs, batch_size=32, Adam optimizer
- Dataset: MNIST subset (5000 train, 1000 test)

CODE LOGIC:
  for act in ['relu', 'tanh', 'sigmoid']:
      - Define MLPActivation with chosen activation
      - Train for 10 epochs
      - Compute test accuracy
      - Plot loss curves

EXPECTED RESULTS:
- ReLU typically: 0.90-0.92 accuracy (stable gradients)
- Tanh typically: 0.90-0.93 accuracy (centered output)
- Sigmoid typically: 0.85-0.89 accuracy (vanishing gradient risk)

VIVA ANSWER:
"Activation functions control non-linearity and gradient flow. ReLU provides 
sparse activation and avoids saturation. Tanh centers outputs around 0, improving
convergence. Sigmoid suffers from vanishing gradients in deep networks. In our 
test, Tanh showed best accuracy due to better gradient behavior."

SUB-EXPERIMENT 2: Depth Impact
REQUIREMENT:
- Train neural networks with different numbers of hidden layers and compare 
  their performance.

IMPLEMENTATION:
- Class: MLPDepth (nn/Module) with variable hidden layers
- Tests: 1, 2, 3, 4 hidden-layer networks
- Architecture variant:
  - Depth 1: 784 -> 128 -> 10
  - Depth 2: 784 -> 128 -> 128 -> 10
  - Depth 3: 784 -> 128 -> 128 -> 128 -> 10
  - Depth 4: 784 -> 128 -> 128 -> 128 -> 128 -> 10
- Training: 10 epochs per depth

CODE LOGIC:
  for d in [1, 2, 3, 4]:
      - Create MLPDepth(d)
      - Train for 10 epochs
      - Track convergence epoch (argmin of loss)
      - Compute test accuracy

EXPECTED RESULTS:
- Depth 1: ~0.92 accuracy, converges in ~8 epochs
- Depth 2: ~0.93 accuracy, converges fastest (~6 epochs)
- Depth 3: ~0.92 accuracy, converges in ~7 epochs
- Depth 4: ~0.91 accuracy, converges slowest (~9 epochs, overfitting begins)

VIVA ANSWER:
"Depth 2 provides best balance: sufficient representational capacity without
over-parameterization. Depth 1 lacks expressiveness. Depth 3-4 suffer from 
vanishing gradients and overfitting. Optimal depth depends on dataset complexity;
for MNIST, 2-3 layers are ideal."

SUB-EXPERIMENT 3: Convergence Behavior
REQUIREMENT:
- Evaluate how model depth influences convergence and accuracy on a given dataset.

IMPLEMENTATION:
- Metric: Convergence epoch = argmin(loss per depth)
- Tracked across all depth variants
- Loss curve analyzed for smoothness and plateau speed

CODE LOGIC:
  convergence_epoch = np.argmin(losses)  # For each depth
  - Plots loss trajectory across epochs
  - Identifies when validation loss stabilizes
  - Compares convergence speed across architectures

MEASURED VALUES (from latest run):
- Depth 1: Converges at epoch 8
- Depth 2: Converges at epoch 6 (fastest)
- Depth 3: Converges at epoch 7
- Depth 4: Converges at epoch 9 (slowest)

VIVA ANSWER:
"Convergence speed indicates training efficiency. Depth 2 converges fastest 
because gradient flow is optimal with 1 hidden layer. Deeper networks (3-4) 
show slower convergence due to gradient scaling issues. Shallow networks (1) 
may converge quickly but reach lower accuracy."

SUB-EXPERIMENT 4: Stability and Output Predictions
REQUIREMENT:
- Analyze the impact of activation functions on training stability and output 
  predictions.

IMPLEMENTATION:
- Metric 1: Training loss variance (smoothness of loss curves)
- Metric 2: Final accuracy (output quality)
- Visual: Side-by-side loss plots for all activations
- Analysis: Gradient behavior (ReLU sparse, Tanh dense, Sigmoid saturated)

CODE LOGIC:
  - Plot loss curves for all 3 activations
  - Overlay depth-specific loss curves
  - Identify oscillations/spikes (instability markers)
  - Compare final layer outputs (logits range)

MEASURED STABILITY (from latest run):
- ReLU: Stable, consistent descent, no oscillations
- Tanh: Very stable, smooth convergence, good centering
- Sigmoid: Less stable, occasional spikes, slower initial descent

VIVA ANSWER:
"Training stability refers to consistent loss descent without oscillations. 
Tanh showed most stable training due to output centering and symmetric gradient
flow. ReLU is sparse but still stable. Sigmoid exhibits less stability due to 
saturation at extremes. For production, we prefer Tanh or ReLU for their 
stability properties."

OVERALL OBJECTIVE:
Develop a convolution-based model for image classification and analyze pooling,
feature maps, and convolution parameters.

SUB-EXPERIMENT 1: CNN vs Fully Connected Baseline
REQUIREMENT:
- Develop a convolution-based model for image classification and compare its 
  performance with a fully connected model.

IMPLEMENTATION:
- Class CNN: Conv2D(1,32,3) + ReLU + MaxPool(2) + Conv2D(32,64,3) + ReLU + MaxPool(2) + FC
- Class FC (baseline): Dense layers only (2D images flattened to 1D)
- Both: Input MNIST 28x28 -> 10 classes
- Training: 10 epochs, batch_size=32

CODE LOGIC:
  cnn_model = CNN()
  fc_model = FC()  # Same MNIST data, no convolutions
  - Train both for 10 epochs
  - Compare accuracies
  - Report: CNN_acc vs FC_acc

EXPECTED RESULTS:
- CNN typical: ~0.96-0.97 accuracy (spatial structure preserved)
- FC baseline typical: ~0.94-0.95 accuracy (position-invariant)

VIVA ANSWER:
"CNNs exploit spatial locality through convolutions: adjacent pixels are 
processed together, learning local features (edges, corners). FC networks lose
spatial information, treating all pixels equally. Result: CNN outperforms FC 
by ~2% on MNIST because spatial structure matters for digit recognition."

SUB-EXPERIMENT 2: Pooling Layer Analysis
REQUIREMENT:
- Analyze the role of pooling layers in improving model performance and 
  reducing overfitting.

IMPLEMENTATION:
- Class CNNPool: Variant with different pooling strategies
- Tests: MaxPooling(2), AveragePooling(2), MaxPooling(4)
- Same conv backbone, different pooling configs
- Training: 10 epochs per config

CODE LOGIC:
  for pool_type, kernel_size in [('max',2), ('avg',2), ('max',4)]:
      - Build CNN variant with pooling
      - Train for 10 epochs
      - Measure: accuracy, feature map dimensions, computation time
      - Compare overfitting (train loss vs validation loss gap)

EXPECTED RESULTS:
- MaxPool(2): ~0.96 accuracy, moderate compression
- AvgPool(2): ~0.95 accuracy, smoother but less selective
- MaxPool(4): ~0.94 accuracy, aggressive compression, lost information

VIVA ANSWER:
"Pooling reduces spatial dimensions, achieving translation invariance and 
computational efficiency. MaxPooling selects strongest activations (edges), 
preserving salient features. AveragePooling blurs features, losing sharpness. 
Larger kernels compress more, risking information loss. MaxPool(2) offers 
best balance of compression and feature preservation."

IMPLEMENTATION:

- Visualize representative samples (first 4-8 filters per layer)

CODE LOGIC:
  - Forward pass through first sample
  - Extract activation maps from Conv1, Conv2
  - Plot grid: Conv1 shows edges/blobs, Conv2 shows shapes/patterns
  - Analyze: filter specialization, information hierarchy

INTERPRETATION:

  - Filter 1: Diagonal edges
  - Filter 2: Horizontal bars
  - Filter 3: Vertical strokes
  - etc.

  - Filter 2: Vertical segments (useful for 1, 7)

VIVA ANSWER:
"Early layers learn low-level spatial patterns (edges). Deeper layers compose
these into high-level features (shapes, parts). This hierarchical learning is
CNN's key strength. Feature visualization confirms that convolutions discover
semantically meaningful patterns without explicit supervision."

count = capacity: more filters = more features learned, but slower training and
risk of overfitting. 3x3 with 64 filters balances accuracy, speed, and 
generalization for MNIST."

EXP 3: TRANSFER LEARNING - transfer_learning.py
================================================================================

OVERALL OBJECTIVE:
Adapt a pretrained model for a new classification task using feature 
extraction and fine-tuning.

SUB-EXPERIMENT 1: Frozen Feature Extractor
REQUIREMENT:
- Adapt a pretrained model for a new classification task using feature 
  extraction.

IMPLEMENTATION:
- Model: MobileNetV2 pretrained on ImageNet
- Strategy: All layers frozen, only new head (classification layer) trained
- Head: GlobalAvgPool -> Linear(1280 -> 10)
- Task: Binary classification on synthetic 100 samples
- Training: 5 epochs on frozen features

CODE LOGIC:
  model = torchvision.models.mobilenet_v2(pretrained=True)
  # Freeze all parameters
  for param in model.parameters():
      param.requires_grad = False
  # Add new head
  model.classifier = nn.Sequential(
      nn.Dropout(0.2),
      nn.Linear(1280, 10)
  )
  # Train only classifier head for 5 epochs

EXPECTED RESULTS:
- Training loss: Rapid descent (pretrained features are already good)
- Final accuracy: ~0.88-0.92 (limited by synthetic data, not model)
- Training time: ~2-3 seconds (small classifier head)

VIVA ANSWER:
"Feature extraction leverages pretrained knowledge: ImageNet-trained features
recognize general visual patterns (edges, textures, shapes). We reuse these 
without modification and train only the classification head. This is extremely
efficient: requires minimal data, trains fast, achieves good accuracy with 
small dataset. Downside: limited to patterns learned on ImageNet."

SUB-EXPERIMENT 2: Fine-Tuning vs Frozen
REQUIREMENT:
- Compare performance when using frozen layers versus partial fine-tuning.

IMPLEMENTATION:
- Frozen: All layers frozen (Experiment 1)
- Fine-tuned: Unfreeze last 20 layers, train with low learning rate 1e-5
- Both: Same synthetic data, 5 epochs
- Comparison: Accuracy, convergence, training time

CODE LOGIC:
  # Fine-tuning variant
  model = torchvision.models.mobilenet_v2(pretrained=True)
  # Freeze early layers
  for param in model.features[:-20].parameters():
      param.requires_grad = False
  # Allow last 20 layers to train
  for param in model.features[-20:].parameters():
      param.requires_grad = True
  # Train with low LR (1e-5) for stable fine-tuning

EXPECTED RESULTS:
- Frozen: Quick convergence, acc ~0.88-0.92, 2s training
- Fine-tuned: Slower convergence, acc ~0.90-0.94, 8s training, risk of overfitting

VIVA ANSWER:
"Fine-tuning adapts pretrained features to your data by unfreezing later layers.
Pros: can improve accuracy on domain-specific data. Cons: requires more data, 
longer training, risk of overfitting if dataset is tiny. Our small synthetic 
dataset barely shows improvement, confirming that fine-tuning benefits from 
larger, domain-specific data."

SUB-EXPERIMENT 3: Small Dataset Learning
REQUIREMENT:
- Analyse how pretrained features improve learning on small datasets.

IMPLEMENTATION:
- Data sizes: 50 samples, 100 samples, 200 samples
- Training: Frozen features (same head for all)

CODE LOGIC:
  for dataset_size in [50, 100, 200]:

      - Create frozen MobileNetV2

      - Compare across sizes

EXPECTED RESULTS (with frozen features):
- 50 samples: ~0.85 accuracy (limited diversity)
- 100 samples: ~0.88 accuracy (better coverage)
- 200 samples: ~0.92 accuracy (sufficient signal)

From-scratch training on same data (conceptual):
- 50 samples: ~0.60 accuracy (catastrophic underfitting)
- 100 samples: ~0.65 accuracy (severe overfitting risk)

VIVA ANSWER:
"Transfer learning shines on small datasets. With frozen pretrained features,
our tiny 50-sample dataset achieves 0.85 accuracy because we leverage 1M

SUB-EXPERIMENT 4: Training Efficiency
REQUIREMENT:
- Evaluate training efficiency when only selected layers are updated.

IMPLEMENTATION:
- Metric 1: Training time (frozen vs fine-tuned)
- Metric 2: Parameter count (trainable vs total)
- Metric 3: Gradient computation (frozen backprop is cheaper)
- Metric 4: Memory usage

CODE LOGIC:
  frozen_params = sum(p.numel() for p in model.parameters() if p.requires_grad)
  total_params = sum(p.numel() for p in model.parameters())
  efficiency_ratio = frozen_params / total_params
  
  # Frozen: train only ~1K head params out of 2.3M total
  # Fine-tuned: train ~500K params (last 20 layers)
  
  frozen_time = measure_training_time(frozen_model, 5_epochs)
  finetune_time = measure_training_time(finetuned_model, 5_epochs)

EXPECTED RESULTS:
- Frozen: 1K trainable / 2.3M total = 0.04% efficiency ratio, ~2s per epoch
- Fine-tuned: 500K trainable / 2.3M = 21.7% ratio, ~2.5s per epoch
- Memory: Frozen uses ~1.2 GB, Fine-tuned uses ~1.8 GB
- Gradient computation: Frozen is 5x faster (fewer backprop operations)

VIVA ANSWER:
"Efficiency gains from freezing are substantial: 0.04% trainable params means
we compute gradients for only 1280-dimensional head, not 2.3M-dimensional 
network. Result: 5x faster training, 40% lower memory, ideal for edge devices.
Trade-off: less adaptability. Fine-tuning trades off efficiency for accuracy
on domain-specific data. Choose based on data quantity and target constraints."

OVERALL OBJECTIVE:
Study hyperparameter effects on model convergence, generalization, and overall
performance via systematic analysis.

SUB-EXPERIMENT 1: Learning Rate Effect
REQUIREMENT:
- Study the effect of learning rate on model convergence and stability.

IMPLEMENTATION:
- Model: Fixed CNN architecture
- Learning rates: 0.001, 0.01, 0.1
- Training: 20 epochs per LR, batch_size=32
- Metrics: Loss trajectory, final accuracy, convergence speed

CODE LOGIC:
  learning_rates = [0.001, 0.01, 0.1]
  results_lr = {}
  
  for lr in learning_rates:
      model = CNN()
      optimizer = optim.Adam(model.parameters(), lr=lr)
      losses = []
      
      for epoch in range(20):
          # Training loop
          epoch_loss = train_epoch(model, optimizer, ...)
          losses.append(epoch_loss)
      
      results_lr[lr] = {
          'losses': losses,
          'accuracy': evaluate(model, x_test, y_test)
      }

EXPECTED RESULTS:
- LR 0.001: Stable descent, slow convergence, acc ~0.95 (underfitting)
  - Epoch 1: loss ~2.3, converges at ~epoch 18
- LR 0.01: Rapid descent, smooth convergence, acc ~0.97 (optimal)
  - Epoch 1: loss ~1.8, converges at ~epoch 8
- LR 0.1: Aggressive descent, oscillations, acc ~0.94 (divergence risk)
  - Epoch 1: loss ~1.5, but spikes appear, converges at ~epoch 15 if stable

VIVA ANSWER:
"Learning rate controls step size in gradient descent. Too small (0.001): 
takes forever (18 epochs). Too large (0.1): overshoots minima, causing 
oscillations/divergence. Optimal (0.01): balances speed and stability, 
converges in ~8 epochs. Rule of thumb: start with 0.001, increase 10x if 
convergence too slow, decrease if loss spikes. Adaptive optimizers like Adam 
adjust LR automatically, reducing need to tune manually."

SUB-EXPERIMENT 2: Epoch Count Effect
REQUIREMENT:
- Analyse how increasing epochs influence overfitting and generalisation.

IMPLEMENTATION:
- Model: Fixed CNN
- Epochs: 5, 10, 15, 20
- Track: Training loss, validation loss (proxy: loss on later batches)
- Metrics: Training accuracy, test accuracy, overfitting gap

CODE LOGIC:
  epoch_counts = [5, 10, 15, 20]
  results_epoch = {}
  
  for num_epochs in epoch_counts:
      model = CNN()
      optimizer = optim.Adam(model.parameters())
      train_losses = []
      test_losses = []
      
      for epoch in range(num_epochs):
          train_loss = train_epoch(model, ...)
          test_loss = eval_epoch(model, x_test, y_test)
          train_losses.append(train_loss)
          test_losses.append(test_loss)
      
      results_epoch[num_epochs] = {
          'train_losses': train_losses,
          'test_losses': test_losses,
          'train_acc': ...,
          'test_acc': ...
      }

EXPECTED RESULTS:
- 5 epochs: Train acc ~0.93, Test acc ~0.93 (underfitting)
- 10 epochs: Train acc ~0.96, Test acc ~0.96 (optimal)
- 15 epochs: Train acc ~0.97, Test acc ~0.96 (early overfitting signs)
- 20 epochs: Train acc ~0.98, Test acc ~0.95 (clear overfitting: gap widens)

Overfitting gap (train_acc - test_acc):
- 5 epochs: 0% (both underfitted)
- 10 epochs: ~0.5% (minor gap, healthy)
- 15 epochs: ~1.5% (gap visible)
- 20 epochs: ~3% (concerning overfitting)

VIVA ANSWER:
"Epochs = number of passes through training data. Early epochs: model learns
general patterns (good). Later epochs: model memorizes training noise 
(overfitting). Sweet spot: when test accuracy plateaus while training loss 
still descends. For MNIST with our data, 10 epochs is ideal. Beyond 10, test
accuracy plateaus or degrades while training accuracy rises. Early stopping 
(stop when validation metric stops improving) automates epoch selection."

SUB-EXPERIMENT 3: Train vs Validation Loss Curves
REQUIREMENT:
- Plot and interpret training vs validation loss curves.

IMPLEMENTATION:
- Model: Fixed CNN
- Training: 20 epochs, track loss on both training and validation
- Validation: Use separate validation split (20% of training data)
- Plot: Overlay train and val loss curves

CODE LOGIC:
  train_loss_history = []
  val_loss_history = []
  
  for epoch in range(20):
      # Training
      train_loss = 0
      for x_batch, y_batch in train_loader:
          output = model(x_batch)
          loss = criterion(output, y_batch)
          loss.backward()
          optimizer.step()
          train_loss += loss.item()
      train_loss_history.append(train_loss / len(train_loader))
      
      # Validation (different data)
      model.eval()
      val_loss = 0
      for x_val, y_val in val_loader:
          output = model(x_val)
          loss = criterion(output, y_val)
          val_loss += loss.item()
      val_loss_history.append(val_loss / len(val_loader))

essentially zero. Network can't learn that first char influences prediction. 
This is THE fundamental limitation. Solution: LSTM/GRU use gating mechanisms 
to preserve gradients. Example: LSTM's cell state uses addition (not 
multiplication), allowing constant gradient flow. That's why LSTM >> RNN for 
long sequences."

Develop a sequence model optimized for faster training, comparing with LSTM,

SUB-EXPERIMENT 1: GRU vs LSTM Comparison
REQUIREMENT:
- Develop a sequence model optimised for faster training.
- Compare performance and training time with another recurrent architecture 
  (LSTM).

IMPLEMENTATION:
- Model 1: GRU(input=1, hidden=64) + Linear(64->num_chars)
- Model 2: LSTM(input=1, hidden=64) + Linear(64->num_chars) [from EXP 8]
- Training: 20 epochs, measure time and accuracy

CODE LOGIC:
  class GRU(nn.Module):
      def __init__(self):
          super().__init__()
          self.gru = nn.GRU(1, 64, batch_first=True)  # 2 gates (reset, update) vs LSTM's 3
          self.fc = nn.Linear(64, len(chars))
      
      def forward(self, x):
          out, h_n = self.gru(x)
          out = self.fc(out[:, -1, :])
          return out
  
  model_gru = GRU()

  time_gru = time.time() - start_gru

  start_lstm = time.time()
  _, acc_lstm = train_model(model_lstm, x_train, y_train, epochs=20)
  time_lstm = time.time() - start_lstm
  
  print(f"GRU: acc={acc_gru:.4f}, time={time_gru:.2f}s")
  print(f"LSTM: acc={acc_lstm:.4f}, time={time_lstm:.2f}s")

- Speed: LSTM faster this run (hardware-dependent; GRU often wins on GPU)

INTERPRETATION:
- GRU: 3 x hidden_size parameters (reset, update gates + content vector)

OVERALL OBJECTIVE:
Implement a generative model to create synthetic data samples, analyzing
training dynamics, generator/discriminator performance, and output quality.

SUB-EXPERIMENT 1: Generator and Discriminator Setup
REQUIREMENT:
- Implement a generative model to create synthetic data samples.

IMPLEMENTATION:
- Generator: 3-layer MLP, noise (100d) -> 784 (28x28 image), output Sigmoid
  - Architecture: 100 -> 256 -> 512 -> 784, ReLU + Sigmoid
  - Purpose: Map noise to fake images
- Discriminator: 3-layer MLP, image (784d) -> 1 (binary: real or fake)
  - Architecture: 784 -> 512 -> 256 -> 1, LeakyReLU + Sigmoid
  - Purpose: Distinguish real from fake
- Loss: Binary Cross-Entropy (BCE) for both
- Optimizer: Adam(lr=0.0002) for both

CODE LOGIC:
  class Generator(nn.Module):
      def __init__(self):
          super().__init__()
          self.main = nn.Sequential(
              nn.Linear(100, 256),
              nn.ReLU(),
              nn.Linear(256, 512),
              nn.ReLU(),
              nn.Linear(512, 784),
              nn.Sigmoid()  # Output in [0, 1]
          )
      
      def forward(self, z):
          return self.main(z)
  
  class Discriminator(nn.Module):
      def __init__(self):
          super().__init__()
          self.main = nn.Sequential(
              nn.Linear(784, 512),
              nn.LeakyReLU(0.2),
              nn.Linear(512, 256),
              nn.LeakyReLU(0.2),
              nn.Linear(256, 1),
              nn.Sigmoid()  # Output probability (real=1, fake=0)
          )
      
      def forward(self, x):
          return self.main(x)
  
  G = Generator()
  D = Discriminator()
  opt_g = optim.Adam(G.parameters(), lr=0.0002)
  opt_d = optim.Adam(D.parameters(), lr=0.0002)
  criterion = nn.BCELoss()

EXPECTED RESULTS:
- Generator learns to map noise -> plausible digit-like images
- Discriminator learns to distinguish real MNIST from fake G outputs
- Training succeeds if: G generates increasingly realistic images, D maintains ~50% accuracy

VIVA ANSWER:
"GANs are two-player games: Generator (counterfeiter) vs Discriminator
(detective). G wants to fool D; D wants to catch fakes. Equilibrium: both
are equally skilled. Architecture: G has no spatial assumptions (uses MLPs),
learns feature hierarchy implicitly. D is binary classifier (real vs fake).
Success metric: visual quality of G samples, not test accuracy (no ground truth
for fake). Training can be unstable (mode collapse, oscillation); careful
hyperparameter tuning needed."

SUB-EXPERIMENT 3: Generator vs Discriminator Performance
REQUIREMENT:
- Compare generator and discriminator performance during training.

IMPLEMENTATION:
- Track: Loss for both G and D, accuracy of D on real vs fake samples
- Plot: Loss curves, D accuracy trajectory

CODE LOGIC:
  gen_losses = []
  disc_losses = []
  disc_accs = []
  
  for epoch in range(20):
      # Discriminator training
      real = real_batch  # Real MNIST samples
      fake = G(torch.randn(batch_size, 100))
      
      D.zero_grad()
      loss_real = criterion(D(real), torch.ones(batch_size, 1))
      loss_fake = criterion(D(fake.detach()), torch.zeros(batch_size, 1))
      loss_d = loss_real + loss_fake
      loss_d.backward()
      opt_d.step()
      
      # Generator training
      G.zero_grad()
      fake = G(torch.randn(batch_size, 100))
      loss_g = criterion(D(fake), torch.ones(batch_size, 1))
      loss_g.backward()
      opt_g.step()
      
      gen_losses.append(loss_g.item())
      disc_losses.append(loss_d.item())
      
      # D accuracy on real vs fake
      with torch.no_grad():
          acc_real = (D(real) > 0.5).float().mean().item()
          acc_fake = (D(fake) < 0.5).float().mean().item()
          overall_acc = (acc_real + acc_fake) / 2
      disc_accs.append(overall_acc)

EXPECTED RESULTS (from latest run):
- Gen Loss: Starts ~2.0 (random guessing), decreases to ~1.5-2.0 (stable but not converged)
- Disc Loss: Starts ~1.4, oscillates ~1.2-1.5 (both trying to win)
- Disc Accuracy: Starts ~60% (learns quickly), settles ~50% (perfect: can't distinguish)
  - Early: D easily spots fake (pure noise)
  - Late: D stumped, 50% accuracy (G improved)

IDEAL CONVERGENCE:
- Both losses converge to ~0.69 (log(2), entropy of 50-50 guess)
- D accuracy -> 50% (random guessing, can't distinguish)
- Interpretation: G and D reached Nash equilibrium

VIVA ANSWER:
"D loss decreases early (learns real/fake quickly), then stabilizes. G loss
decreases (learns to fool D). Ideal convergence: both losses ~ 0.69 (random
guessing), D accuracy ~ 50% (stumped). Our curves show oscillation (common in
GANs), where G and D take turns winning. This is sign of healthy competition.
If D loss -> 0 and stays there: D too strong (G can't improve). If G loss
stays high: G can't fool D (bad initialization). Our training shows G improving
over epochs, D adjusting, suggesting healthy adversarial dynamics."
